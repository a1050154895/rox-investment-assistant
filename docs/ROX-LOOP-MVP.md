# ROX Loop MVP

## 定位

ROX 的第一条增长型核心工作流是：

```text
今日队列 → 研究卡 → 事实 / 假设 / 反证 → 确定性风控 → 决策 → 复盘
```

ROX 不替用户荐股，而是帮助主动投资者把一次投资判断变成可验证、可追踪、可复盘的研究资产。

## 本轮已实现

- `ResearchCard` 数据模型，按用户隔离保存。
- `/api/research/today`：返回未归档研究卡、待复盘决策和下一步动作。
- `/api/research/`：研究卡 CRUD。
- `/api/research/{id}/risk-check`：检查研究问题、核心假设、事实、反证和失效条件是否齐备。
- 首页增加“今日研究队列”，把研究卡作为主入口。
- 新增 `/research` 和 `/research/{id}` 页面。
- 个股 K 线优先使用 TradingView Lightweight Charts；ECharts 作为前端降级路径。
- 个股页可一键创建研究卡，并自动带入标的、价格、数据状态、来源和数据日期。
- `JournalEntry.research_card_id` 将正式决策关联到研究卡，形成研究前后的可追踪链路。
- 研究卡支持假设状态：成立、部分成立、失效、未验证。
- 研究卡支持 `next_review_at`，首页研究队列展示下次复核日期。
- 基金/ETF支持价格风险指标、数据覆盖矩阵和关联决策。

## 数据边界

当前 K 线仍由既有后端行情服务提供，图表库只负责展示和交互，不会把历史快照标成实时数据。实时行情接入必须由后端适配器完成，并继续携带 `data_status`、`data_source`、`as_of` 和 `stale` 字段。

TqSdk 已在本地 Python 3.13 环境做过导入验证，但 `tqsdk==1.3.2` 依赖已移除的 `asyncio.coroutine`，当前环境不能直接作为生产依赖使用。下一步应在 Python 3.11 隔离运行时中做 dry-run，并确认账号、行情授权、连接稳定性和部署成本后再接入。

## 移动端阶段验收记录

本阶段完成了今日页、个股页、研究卡、决策日志和复盘页的移动端改造，并在本地浏览器用 375px、390px、414px 宽度验收：

- 页面 `document` 宽度与视口一致，无横向溢出。
- 研究卡手机端按 4 步显示，点击下一步后只展示下一步内容。
- 个股页操作区、K 线容器和分析区在 390px 下能正常排列。
- 决策日志筛选区、时间线和复盘页统计/板块区在 390px 下能正常加载。
- 首次登录新手引导在手机端可读，但会覆盖工作区；后续应改为不遮挡核心任务的引导状态。

Lightweight Charts 只负责 K 线交互展示，不代表行情源已经变成实时。实时/快照/过期状态仍由后端行情服务负责标注；TqSdk 仍需在 Python 3.11 与授权环境中单独验证后才能接入。

## 当前产品边界

研究卡是 ROX 的唯一核心对象。股票、ETF、基金、指数、行业、概念和宏观主题都应通过证据进入研究卡，再进入决策和复盘。

AI 是增强层而非核心依赖：无 AI 时研究、风控、决策和复盘仍完整可用；平台 AI 只做整理、解释、追问和归纳；BYOK 是高级可选能力。

GlobalPulse 可参考其专题主线、热度排序、突发提醒和多来源组织，但 ROX 不复制情绪预测、次日方向置信度或高强度交易终端视觉，而是把事实整理成可验证的研究问题。

## 下一轮优先级

1. 实现跨页面证据抽屉：来源、时间、传导路径、行业影响和验证动作。
2. 让情报、股票、ETF、宏观页面一键把证据加入研究卡，并标记事实/假设/反证/待验证。
3. 扩展研究卡生命周期：研究中、待验证、待决策、观察中、已复盘、已失效。
4. 建立统一 DataSourceRegistry 和全对象数据覆盖矩阵。
5. 在确认数据授权后，再接入 TqSdk、基金净值/IOPV/持仓或其他实时源；没有可靠源时保持诚实降级。

## 验收指标

- 新用户 10 分钟内完成第一张研究卡。
- 每张正式研究卡至少包含 1 个事实、1 个假设、1 个反证和 1 个失效条件。
- 保存后能运行风控检查，并明确显示缺失项。
- 首页能告诉用户下一步做什么，而不是只展示行情。
